## BUG-2541 · Magpie 超分导致校准采集与已校准内嵌查词失效

### 第十四轮调查：自绘光标与系统坐标不同（2026-09-19）

用户新增反馈为“可见鼠标在台词下方，却高亮台词中的字”。本机 Magpie 日志显示实际版本 **v0.12.1**，安装目录名不能作为版本证据。对照官方 [CursorManager.cpp（固定提交）](https://github.com/Blinue/Magpie/blob/664e0f4c8a9aca4e6efb0e37f52be6dc62414f7b/src/Magpie.Core/CursorManager.cpp) 的 `SrcToScaling` 和捕获状态切换：捕获期间系统坐标位于源窗口，Magpie 将它映射到目标视口绘制光标；光标按首末像素映射，比例为 `(目标长度 - 1) / (源长度 - 1)`，不同于字框的矩形缩放。退出捕获后不能再次缩放坐标。仅研究公开坐标协议并独立实现必要换算，没有将第三方源码复制进生产构建。

原 `TickHoverLookup` 直接将 `GetCursorPos` 减呈现层原点，低层点击也直接用 `MSLLHOOKSTRUCT::pt` 匹配已放大的字框，二者均缺少光标空间转换。只改截图几何或弹窗锚点不能修复这个输入问题。

用户授权只读现场诊断，未移动鼠标、点击或切换窗口。30秒采样共150次，其中3次读取到呈现窗透明捕获状态；例如系统 `(3089,367)` 按官方公式对应呈现 `(3447,124)`。这证明两种坐标不能混用，但不是连续台词悬停/点击验收。身份、映射和原始采样仅存本机 ignored `.codex-test/round14-live/`。源码候选及最终验证以当前交接为准。

候选让悬停、点击按下和抬起使用同一光标转换；命中快照同时保存源/目标视口和已验证的呈现 HWND。鼠标钩子只增加一次已绑定 HWND 的样式读取，不枚举窗口、不读属性、不做同步消息或跨进程调用；非透明捕获状态拒绝旧快照，按下后退出捕获则取消查词提交并继续回收实际按键事务。通过既有同步路径重新发布，未新增轮询定时器。呈现 HWND 变化即使几何相同也会重新发布，避免 Magpie 重建窗口后保留旧目标。

`attached_magpie_surface_geometry_test.cpp` 覆盖首末像素、负屏幕原点舍入、视口外偏移、两种空间命中不同字、捕获失效及按下后退出捕获；原有输入非阻塞/事务/屏蔽守卫保留。最终贴附层对象 `/W4 /WX` 编译和4个原生测试可执行程序通过：`.codex-test/round14-native-final.log`。几何测试与低层钩子对象编译证据见交接；仍需用户构建后进行普通窗口 → 超分 → 退出超分的实机验收。

### 第十三轮：跨 DPI 的物理客户区误差（2026-09-19，候选）

现场已记录的 `magpie_source_viewport_invalid` 来自真实边界误差：DPI-unaware 源窗口在 175% 显示缩放下，`GetClientRect` 后分别 `ClientToScreen` 把实际 2326 像素的客户区算成 2324。Magpie 公布的 SrcRect 因此被误判越界，截图与贴附查词都被暂停；文本 Hook 仍可正常到达。

`window_capture.cpp::ReadPhysicalClientScreenRect` 改用 `GetWindowInfo.rcClient` 一次读取物理屏幕客户区。贴附层、截图元数据与 DWM 客户区裁剪共用它，保留 SrcRect/DestRect 的严格包含检查。原生几何回归包含实际 `{952,474,3278,1783}`，以及少两像素时仍应拒绝的反例。错误分类另将已知映射失败与“没有台词”分开，日志只记录有界原因和尺寸。

定向测试、原生编译和最终源码提交见 [当前交接](../personal/archive/GAL_LOOKUP_HANDOFF.md)。本轮没有操作用户游戏、切换超分或新采集桌面；普通窗口 → Magpie → 退出后的实机恢复仍需用户验收。

### 当前边界

现有校准契约本来就会拒绝 Magpie 重定向、客户区尺寸不符或缺少完整 metadata 的截图。因此“不能采集”可能是保护性拒绝；但关闭超分后仍不能采集、已校准查词也没有恢复，说明还需要单独调查状态恢复和目标身份变化，不能简单归为“超分不支持”。

后续统一处理时需要对比：

1. Magpie 开启/关闭前后的目标 HWND、PID、客户区物理尺寸、DPI 和捕获 metadata；
2. WGC 捕获是否仍指向游戏客户区，还是变成 Magpie 输出窗口/重定向表面；
3. 现有 profile 的 reference client 与 surface variant 选择是否被尺寸变化拒绝；
4. 关闭 Magpie 后是否重新绑定目标、清理旧 capture lease、恢复 overlay 和已校准查词，而不要求用户重新 Hook。

本条记录不证明 Hook 文本获取失败，也不证明 Magpie 对所有游戏都不兼容；本轮不修复、不编译、不要求用户重复测试。
