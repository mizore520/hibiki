## BUG-2543 · 部分游戏无法采集完整游戏画面

### 当前修订：窗口捕获兼容路径（2026-09-19）

最新《ひこうき雲の向こう側》现场日志显示 `wgc_item_create_failed`，窗口客户区为2240×1260，尚未取得图像/纹理。确认失败边界是 WGC 创建窗口项；尚未由 HRESULT 确认系统拒绝的具体原因，不能归为最小化或 OCR。

- 本批撤去 `ff0ec5605a` 的无依据 WGC 延时重试，保留真实 HRESULT。
- 增加受限的 PrintWindow 兼容采集，独立核对目标身份与客户区；不读取桌面或任意同尺寸窗口。拒绝未绘制、不完整及无有效内容的结果。独立审查发现初版worker无法回收永久阻塞调用，进一步改为同EXE早期专用helper入口、匿名共享内存和Job/进程超时终止，避免一次失败永久占用后端。
- Magpie回退仍要求源/呈现身份、Src/Dest视口和捕获前后的客户区一致，新增可信源裁剪映射。错误提示不再一概要求用户取消最小化；诊断只提取数值错误码进入校准日志。
- 独立审查同时定位到旧截图回传的生命周期竞态：worker持有旧host HWND和Flutter MethodResult，消息投递失败会跨线程调用reply，投递后关窗可能遗失pending。改为主界面持有reply队列，后台只发布结果；关闭窗口时先取消全部请求再销毁messenger，晚回结果不访问窗口。`window_capture_reply_queue_test.cpp`覆盖5个生命周期场景，原生对象编译通过。
- **[x] ① 已实现兼容候选** — 捕获子提交`ee990dd066`后在`cc923a9f55`完成整合与独立审查，移除缺少现场证据的窗口样式硬门，只在WGC创建窗口项失败时尝试。兼容后端有条件限制，不能宣称原游戏已验收。
- **[x] ② 定向验证** — 原生对象、启动入口定向编译通过；合成窗口用完整生产flags真实捕获624×381/1878字节PNG，超时后可再次成功。持久`window_capture_printwindow_helper_test.cpp`独立以shim验证IPC、保留进程句柄确认超时helper已终止、下次请求可用；不是用填色替代真实截图证据。Dart采集/来源回归、启动和捕获源码守卫通过。证据仅覆盖源码与合成窗口，真实游戏仍由用户一次集中运行。

### 现象

用户反馈“有的游戏还弄不了”。校准页在尝试采集当前画面时显示：

> 未能取得完整的游戏画面。请确认游戏窗口未最小化，再采集一次。

因此该游戏无法继续进行截图校准。附件截图只作为现象证据，没有复制进仓库；截图中的提示不能证明游戏当时确实处于最小化状态。用户此前还报告过 Magpie 超分导致采集和已校准查词失效（见 [BUG-2541](BUG-2541-gal-magpie-upscaler-breaks-calibration.md)），本条只记录“完整画面采集失败”这一跨游戏症状，不与其合并归因。

### 待调查边界

后续需要在失败游戏上同时记录窗口是否最小化/遮挡、客户区尺寸、捕获后端返回的帧尺寸与完整性、截图身份以及 Hook 文本状态，再区分窗口状态问题、合成/重定向表面问题、超分或覆盖层干扰、客户区元数据不一致等可能性。不能因为提示文案提到“最小化”就要求用户反复调整窗口，也不能把一次采集失败当作该引擎永远不兼容。

### 本轮边界

用户要求先集中记录问题；本轮不修复、不编译、不运行游戏、不引入新的捕获后端。统一处理时再与 [BUG-2542](BUG-2542-gal-cross-game-calibration-still-not-general.md) 的跨游戏兼容性问题对照调查。
