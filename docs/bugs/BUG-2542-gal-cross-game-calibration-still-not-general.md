## BUG-2542 · 换游戏后自动校准兼容性仍不足，需要逐游戏适配


### 2026-09-19 实施更新（待实机验收）

源码候选：`cea2b6cafb`，原分支本地提交，未合入正式线。

用户已授权统一修复，并确认存在“提示成功但框略偏”。本批将搜索框 `searchRect` 与生成的排版区域 `rect` 分开持久化；旧草稿兼容读取，修改搜索框使旧拟合失效。识别后不再覆盖手动橙框。纠正前次调查：旧 OCR `read` 实际还暗中左右扩 4%、上下扩 12%；现已删除扩张，严格按可见选区裁剪，不能沿用此前“从未扫描框外”的表述。

PP-OCR 的 CTC 帧只提供近似位置。本批增加通用笔画像素校正，依据图像颜色、连通域与字间空隙拟合规则字格，过滤大背景块和重复纹理；无足够笔画证据的长行拒绝发布。短尾行不参与字号/字距估计；实测行优先确定起点、行距和缩进，短尾仅验证已有实测缩进，无该证据时保留受规则约束的近似行对应。逐字与真实 native preview 核对索引、中心及笔画是否落在字框内，不能以未溢出等同准确。

两行末尾三角附件的本机预览复现中，OCR 输出未包含三角；拒绝原因是短尾行标点的 CTC 位置污染字距。修复后该预览可拟合。附件经过 UI 缩放且正文人工转写，仅作诊断，不冒充原始 Hook/游戏采集验收。另外补齐普通日文小假名的一格行末禁则，未引入游戏名特例。

现存六组 11 张保存截图通过真实 PP-OCR 推理、Hook 对应、像素校正、native preview 和叠框复查。回放使用本机 Python ONNX Runtime 执行同一模型、生产 Dart 预后处理；未验证应用内 session 装配与新句点击，不能外推跨游戏成功率。相关六个 Dart suite 合计 80 个用例通过（78 项后新增 2 项，受影响 OCR suite 单独回归），原生排版 19 cases 通过。

Tesseract 日文模型完成 13 个本机对照输入，本次识字/字框未显示优势，不引入生产 fallback；该试验不是统一预处理的标准 OCR 排名。PP-OCR medium、MangaOCR 和云端模型也不能仅凭识字能力保证精确位置；本批未上传游戏截图或调用付费云服务。

### 用户现场

- 更换到另一款游戏后，已有的统一校准流程再次不能正常使用。用户担心如果每款游戏都要事先单独训练，适配工作无法结束。
- 截图中画面有完整的两行台词，橙色区域大致包住正文，台词姓名在框外，旁边有游戏按钮和复杂背景。
- 界面提示“暂时无法可靠确定字格。请使用完整的多行台词，把正文框进来，避开名字和按钮；原草稿未改动”。也就是说，即使画面有两行正文，自动字格仍拒绝发布，不能直接进入统一查词流程。
- 当前截图标注的客户区尺寸为 `2240 × 1260`。截图只作为本次对话附件保留，没有复制进仓库。

### OCR 候选后的集中体验反馈

- 用户反馈目前对齐准确度仍然不够，认为这是能否实际使用的核心问题；具体偏移形态、失败样本和实际运行构建尚未核对，不直接归因为 OCR 模型识字错误。
- 本轮收集末尾用户再次强调：当前识别准确度仍远远不够，是特别重要的核心问题。后续不能只修闪退/交互就视为完成；需以本轮失败样本及实际新句对齐效果验收，离线通过数量不能替代体验结果。
- 用户不清楚可拖动的大框与字符小框是否由 OCR 生成，以及引入 OCR 后仍需手动调框的意义。需要明确：大框提供正文搜索范围；字符小框由 OCR 近似位置、Hook 正文和规则排版拟合生成，并非 OCR 直接给出的精确游戏字形边界。
- 用户进一步报告：手动调整外框后点击识别，外框又变大；用户预期只在原选区内识别，保留手动选区。源码确认 OCR 输入按 `draft.rect` 裁剪，但拟合随后重新计算排版区域（含完整行容量向外补齐），界面以 `result.draft.rect` 覆盖原 `_rect`。当前把识别搜索区和生成的排版区域复用为同一个可编辑框，导致手动调整被覆盖、操作语义不清。后续需区分这两个用途，不能把变大的结果框解释为本次 OCR 扫描了原选区之外；具体现场扩大量仍未核对。

### 原始记录的边界

这条记录描述的是跨游戏自动校准泛化失败，不等于 Hook 文本获取失败，也不等于用户没有框住台词。已有的亮/暗/局部对比度检测改进只能覆盖部分画面样式，不能据此宣称“所有游戏通用”。

后续统一处理时需要把成功游戏和本次失败游戏放在同一套离线比较中，分别验证：

1. Hook 正文与截图中的行、字符序列是否能建立稳定对应；
2. 无独立文字框、复杂背景、描边和彩色文字下的行/字迹区域检测；
3. 两行及续行缩进、名字/按钮排除和规则字格拟合是否有多解；
4. 失败时是否能给出明确的不可解原因，而不是把用户推回逐字点中心或逐游戏训练。

本轮只记录，不修复、不编译、不要求用户重复采集或继续手调。
