## BUG-2738 · KiriKiri 查词弹窗上滚动滚轮会让游戏翻到下一句
- **报告**：2026-09-27（用户：《王様恋愛》Ver1.00 / KiriKiri Z，打开游戏内查词后想用滚轮往下看词典，游戏直接翻到下一句）。补充（2026-09-28）：点一下弹窗也仍会翻页；同社（ASa Project）另一作同样复现，其它厂商的 KiriKiri 游戏不复现。
- **真实性**：⚠️ 真 bug，根因未完全确认。用户当次 `hibiki_glookup.log` 里多次卡片在没有任何点击记录的情况下被 dismiss（如 23:30:46 seq=5、23:30:52 seq=7），与「台词变了、查词随之收起」一致。游戏 exe 内含 `tTVPWheelDirectInputDevice`，`-wheel` 选项 `"value":"dinput"` 标 `"default":true`，`.cf` 与用户 `.cfu` 均未改写：本作按引擎缺省经 DirectInput 读滚轮。宿主 `low_level_mouse_hook.cpp` 在光标压在卡片上时吞掉 `WM_MOUSEWHEEL`，但 WH_MOUSE_LL 挡不住 DirectInput。第一版只在 `kag.onMouseWheel` 接缝按浮窗标记消费，复测仍翻页，说明翻页不只经过该接缝（引擎原生层还会把滚轮派给焦点图层，或该社脚本另有读法）。「只有该社复现」尚未解释，可能与其脚本/插件对滚轮的处理有关。
- **[ ] ① 候选修复（待复测）** — 判据统一放在 `native/galgame_hook/hook/host_overlay_probe.inc` `HostOverlayUnderCursor`：每 500 ms 用 EnumWindows 收集「别的进程、owner 属于本进程」的候选窗（宿主贴在游戏上的直连查词卡片、Hook 工具条、悬浮歌词），每帧只对它们做可见、非穿透、矩形与窗口区域命中，不用 WindowFromPoint（避免向游戏同线程窗口发 WM_NCHITTEST）；候选缓存加锁，护盾与 KiriKiri 泵共用。
  - 源头：`generic_input_shield.inc` 的 DirectInput `GetDeviceState` / `GetDeviceData` detour 在登记门之前，对鼠标设备（登记的标准鼠标格式，或按 `GetCapabilities` 判定并缓存）在光标压着浮窗时清掉 `lZ`、删掉 `DIMOFS_Z` 事件；纯数据部分为 `include/generic_input_shield.h` `ClearDirectInputMouseStateWheel` / `RemoveDirectInputWheelEvents`。附着前游戏自建的设备未经工厂 hook，`ProbeGenericDirectInputImplementations` 经已 hook 的工厂自建一个系统鼠标设备（不 Acquire）触发实现级 inline hook 后立即释放，覆盖同一实现的既有设备。
  - 接缝：`kirikiri_adapter.inc` 泵在传感器已活后同步 `global.fushiLookupHostOverlayUnderCursor`，查词关闭、会话结束或停机时写回 0；`fushiLookupMouseWheelHook` 在卡片判定前据此消费。
  - 诊断（有界）：游戏侧 `fushi_galhook.log` 记 `wheel.dinput`（DirectInput 读到滚轮时是否鼠标、是否判为浮窗、是否去掉，≤24 行）、`dinput.probe`、`wheel.seam`（TJS 接缝调用，≤8 行）；宿主侧 `hibiki_glookup.log` 记 `global wheel`（钩子吞下并转交，≤20 行）。复测后据此确认滚轮进入游戏的路径。`HookLogLine` 随之移到 `host_overlay_probe.inc`，两个架构共用。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/generic_input_shield_test.cpp`：lZ 只清滚轮轴、保留位移与按键，未知布局不动；缓冲事件只删 `DIMOFS_Z` 且保序；源码断言两个 detour 在登记门之前处理滚轮且安装路径调用探针。`kirikiri_lookup_source_guard_test.py` `find_host_overlay_wheel_leak`：接缝先看浮窗标记、bootstrap 初始化、泵同步与两条早退复位、浮窗判定不得用 WindowFromPoint，均有变异自测。Win32 窗口判定与 DirectInput 时序没有行为级测试，需实机复测。
- **备注**：新建的浮窗最多 500 ms 后才进入候选（宿主复用同一 HWND 显隐，稳态不受影响）。KAGEX `addHook` 路径下 `onMouseWheelHook` 在 focusedLayer 之后才被调用，焦点层可能先消费滚轮；源头过滤不受此影响。
