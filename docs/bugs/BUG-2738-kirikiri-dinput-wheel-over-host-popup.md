## BUG-2738 · KiriKiri 查词弹窗上滚动滚轮会让游戏翻到下一句
- **报告**：2026-09-27（用户：《王様恋愛》Ver1.00 / KiriKiri Z，打开游戏内查词后想用滚轮往下看词典，游戏直接翻到下一句）。补充（2026-09-28）：点一下弹窗也仍会翻页；同社（ASa Project）另一作同样复现，其它厂商的 KiriKiri 游戏不复现。
- **真实性**：✅ 真 bug（第三轮诊断确认路径）。用户当次 `hibiki_glookup.log` 里多次卡片在没有任何点击记录的情况下被 dismiss（如 23:30:46 seq=5、23:30:52 seq=7）。游戏 exe 内含 `tTVPWheelDirectInputDevice`，`-wheel` 选项 `"value":"dinput"` 标 `"default":true`，`.cf` 与用户 `.cfu` 均未改写。宿主侧 `global wheel` 日志证实每格滚轮都被 WH_MOUSE_LL 吞下并转交给弹窗，但 WH_MOUSE_LL 挡不住 DirectInput。第三轮 `fushi_galhook.log` 显示游戏的滚轮设备每 ~60 ms 调一次 `GetDeviceState`，**`bytes=4`**、`GetCapabilities` 判为鼠标：KiriKiri 为滚轮单建一个只含 Z 轴的 4 字节自定义格式设备。第二版只认 16/20 字节的标准 DIMOUSESTATE 布局，所以虽然 detour 覆盖到（探针 `hooked=1`），却从未处理这台设备。第一版只在 `kag.onMouseWheel` 接缝消费，挡不住引擎原生派发；且本次复测走的是 attachedOnly 贴附层 + 桌面弹窗，KiriKiri 游戏内传感器未安装。「只有 ASa Project 两作复现」可能只是该社把滚轮向下映射为「下一句」，未作为根因证据。
- **[ ] ① 候选修复（待复测）** — 源头：`generic_input_shield.inc` 的 DirectInput `GetDeviceState` / `GetDeviceData` detour 在登记门之前，对鼠标设备（登记的标准鼠标格式，或按 `GetCapabilities` 判定、相对轴模式）按**当前数据格式**里 Z 轴的偏移处理：用 `GetObjectInfo(DIPH_BYOFFSET)` 逐个偏移反查 `GUID_ZAxis`（`EnumObjects` 给的是原生格式偏移，对自定义格式不成立），按设备缓存，`SetDataFormat` 与 Release 到 0 时失效；光标压着宿主浮窗时清掉即时状态的 Z 值、删掉缓冲事件里该偏移的事件。纯数据部分为 `include/generic_input_shield.h` `ClearDirectInputStateAxis` / `RemoveDirectInputAxisEvents` / `DirectInputEventsContainAxis`。附着前游戏自建的设备未经工厂 hook，`ProbeGenericDirectInputImplementations` 在引擎主窗出现后经已 hook 的工厂（dinput A/W、dinput8 A/W）自建一个系统鼠标设备触发实现级 inline hook 后立即释放。
  - 判据：`native/galgame_hook/hook/host_overlay_probe.inc` `HostOverlayUnderCursor`：每 500 ms 用 EnumWindows 收集「别的进程、owner 属于本进程」的候选窗（宿主贴在游戏上的查词卡片、Hook 工具条、悬浮歌词），每帧只对它们做可见、非穿透、矩形与窗口区域命中，不用 WindowFromPoint；候选缓存加锁，护盾与 KiriKiri 泵共用。
  - 接缝：`kirikiri_adapter.inc` 泵在传感器已活后同步 `global.fushiLookupHostOverlayUnderCursor`，三条早退写回 0；`fushiLookupMouseWheelHook` 在卡片判定前据此消费。
  - 诊断（有界）：`dinput.wheel_offset`（每设备每格式一次）、`wheel.dinput`（≤24 行）、`dinput.probe`、`wheel.seam`（≤8 行）、宿主 `global wheel`（≤20 行）。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/generic_input_shield_test.cpp`：按偏移只清 Z 轴（标准布局字节 8 与 KiriKiri 4 字节仅 Z 格式字节 0），保留位移与按键，越界偏移不动；缓冲事件只删 Z 偏移事件且保序；源码断言两个 detour 在登记门之前处理滚轮且安装路径调用探针。`kirikiri_lookup_source_guard_test.py` `find_host_overlay_wheel_leak`：接缝先看浮窗标记、bootstrap 初始化、泵同步与两条早退复位、浮窗判定不得用 WindowFromPoint，均有变异自测。Win32 窗口判定与 DirectInput 时序没有行为级测试，需实机复测。
- **备注**：新建的浮窗最多 500 ms 后才进入候选（宿主复用同一 HWND 显隐，稳态不受影响）。KAGEX `addHook` 路径下 `onMouseWheelHook` 在 focusedLayer 之后才被调用，焦点层可能先消费滚轮；源头过滤不受此影响。
