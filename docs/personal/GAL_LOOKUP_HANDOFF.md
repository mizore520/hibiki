## 当前行为与关键契约

1. Hook 是正文真相，PP-OCRv6 small 只用于校准截图的位置提示。OCR 严格读取用户框内，像素校正后拟合规则字格；默认仅使用当前一张图，直接应用，无需逐字点中心。运行期按保存的规则排版，不持续 OCR。
2. 搜索框与拟合正文区独立。拟合时冻结对应截图尺寸和坐标来源；切换/删除样本不会改变已拟合参数。不同源裁剪范围的图片不能联合拟合。手动、联合样本保留高级入口；透明度滑条与重复状态已移除。
3. 词典持有单例鼠标 Hook 时，精确 `mouseHookBusy / singleton_owned_by_other_hwnd` 不再阻止制卡截图。仍要求目标与正文已同步，native 确认 epoch/generation/token，并由既有 composite lease 隐藏词典卡片。其他失效状态仍拒绝。
4. WGC 创建窗口项失败后可尝试目标窗口的 PrintWindow：可见、未最小化/隐藏、未受保护、身份/客户区稳定；拒绝未绘制、部分像素和全黑帧。不可取消的系统调用隔离到同EXE的专用helper入口，先于Flutter/单实例初始化；最多一个helper，匿名共享内存只传有界像素和元数据，超时由Job/进程终止回收。Flutter reply由UI持有，关闭窗口先取消请求，晚回结果不触碰已关闭的界面。撤去盲重试，不读取桌面；失败保留 HRESULT。
5. Magpie 始终先在源客户区排版，再按 SrcRect → DestRect 分别变换 x/y，并裁掉不可见区域。源 DPI 用于 profile，呈现 DPI 用于屏幕锚点。截图保留真实捕获 HWND/PID及源客户区/视口，应用时将 PNG 上的拟合反投影回源坐标。窗口生命周期触发恢复；映射不完整时隐藏命中层、保留认领。
6. 悬停采用 KiriKiri `fushiLookupPaintHighlight` 的浅蓝半透明填充，无描边。当前候选的小标点实现按游戏保存visual bounds，只缩显示框，hit/advance/换行保持原格；这描述现有实现，不代表需求已完成。用户最新明确否定按笔画降低省略号框高的效果，需要的是特定游戏内个别标点的实际窄占位，待集中修订。

## 当前收集的问题（只记录）

- **高度是固定约束**：用户再次明确，同一套游戏排版内所有字符格高度统一，普通字、顿号、省略号等都不能因笔画大小改变框高。个别字符的特殊处理只涉及实际占位宽度，并限定在该游戏内。
- **标点占位需求理解错误**：用户新图中省略号的框被压成细条，用户要求它保留正常字格高度和占位。特殊的是前面的顿号，用户指出它在该游戏中实际占位比普通一格窄。后续只为该游戏内确认的窄占位字符记录宽度例外，使后续文字位置、命中与换行符合实际排版；保持正常行高，不按笔画大小普遍缩框，也不影响其他游戏。具体字符编码和宽度尚未测量，不预设半格。
- **两行完整选区仍识别失败，错误提示混淆原因**：用户截图的橙框看起来包含完整两行正文，却报“样本1：样本的换行或字格不一致”。只读核对发现UI将文字匹配、置信度、笔画几何、缩进和排版一致性等多种失败映射到同一句提示；目前未定位这次具体reason，不能归因于用户漏框、OCR必然已识别正确或游戏排版不规则。个别字符宽度差异是待查方向，尚非已确认根因。保留本图，后续统一核对失败阶段及改进提示。
- **对话与旁白分别校准并自动选择**：用户提出同一游戏可有两套各自稳定的排版，分别用一张对话图、一张旁白图校准并保留两套参数，运行时优先根据Hook正文首尾的成对引号（如「」）选择对应排版，不把两类样本混成一套参数。这里“前后有框”指对话引号，不是橙色选区或青色字格。引号规则限定于当前游戏；Hook是否保留引号及分类不明确时如何处理待实施前核对。这是有限、可区分的稳定样式，不能直接作为已排除的任意不规则排版拒绝；目前仅为待做优化点。
- **仅保留对话/旁白两个校准位置，特殊字符宽度也分别保存**：用户进一步明确，界面固定为“对话”和“旁白”各一张图，不再提供任意增加其他校准样本的流程；同一游戏内的特殊字符宽度例外须再按对话/旁白区分，不能共用或相互覆盖。切换排版时连同对应的字符推进宽度一起选择，后续文字按所属类别的宽度排列；各套排版内字符格高度仍统一，不按标点笔画缩高。此项是新需求记录，现有多样本入口及运行期契约尚未修改。
