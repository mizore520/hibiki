## 当前行为与数据边界

1. Hook 提供完整正文，PP-OCRv6 small 在校准截图中提供位置线索。严格只读取用户橙框内；搜索框不被生成的字格范围覆盖。运行期仍按保存规则排版，不逐句 OCR。
2. 工作台提供“对话”“旁白”两个可选位置，各最多一张图。只完成任意一个时全部正文共用；两套都有时以首尾成对 `「」` / `『』` 选择。内嵌引号不把旁白变成对话；Hook 丢失外引号的游戏不能据此保证分类正确。
3. 槽草稿分别保存在游戏 hash 的 `.dialogue.json` / `.narration.json`；旧 `hash.json` 只作可读种子，不覆盖或删除。旧共用 profile 继续读取。拟合坐标保留真实截图客户区及裁剪来源，应用到超分时依原有投影映射回源窗口。
4. 所有字符格高度统一。`characterAdvances` 仅保存由普通字前后距离支持的实际宽度差，随游戏及对话/旁白排版选择，影响后续文字、命中与换行；不用标点笔画宽高当占位。旧 `punctuationVisualBounds` 兼容读取但不再缩显示框，新拟合不生成它。行容量支持小数，行末禁则最多悬挂一格。
5. OCR 漏掉部分字或个别位置偏差不会直接否决整行；像素无法测量时保留 OCR 候选，再以 Hook 对应、整体位置及 native 行号验证。显式 Hook 换行可用；没有自然折行证据时右侧容量参考用户选区，不能据本图推断所有新句的自动换行。
6. 失败分别说明未检测到文字、正文对应不足、字距/行距不足、缩进、换行、字符位置偏差或原生预览不可用；详情保留不含对白的 reason/行号/误差。真正只有单行且无行距依据时仍需一张两行图，不让用户逐字点中心。
7. 附着修复定位到旧停止在异步回收后清除新会话的竞态，通过 generation 与共享清理 Future 处理；另审查旧 poll/retry/rebind 回调不得清除新会话的在途标记。受控回归与用户 anemoi 现场是两种证据，尚无原现场已解决的实机结论。

## 一次集中实机验收

用户在本工作区运行 `启动Hibiki最新版.bat`，从源码候选 `d18c9815a6`（或其文档提交后继）构建 Windows x64 一次。保留已有草稿；测试顺序：

1. 最新两行误判图重新识别并应用。只校准任意一类，检查对话、旁白都能查词；排版确实不同再补第二类，换句确认自动选择。
2. 看顿号等实际窄占位是否正确带动后续文字，省略号与普通字框高一致；鼠标浅蓝悬停、点击查词不推进游戏。换一条未参与校准的新句检查。
3. 停止监听后重新附着，观察新正文能到达、状态不被旧会话清掉；失败保留时间和提示，不反复重编。
4. 同一次运行正常窗口 → Magpie → 退出 Magpie，各试采集与查词；再试词典制卡及之前不能截图的游戏。此项保留上批验收缺口，不宣称本轮重新实现。
